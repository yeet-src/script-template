# bootstrap

Tiny bash scaffold for new yeet example projects. Writes a starter
directory laid out like this:

```
<name>/
  src/
    bpf/<stem>.bpf.c   — minimal XDP noop with a ringbuf event + .bss counter
    main.js            — loads the object, attaches the prog, drains events
  bin/<slug>           — launcher: execs `yeet run ./src`
  scripts/
    common.sh          — POSIX sh helpers (sourced by rolecall; no exec bit)
    rolecall.sh        — POSIX sh, invoked by `make rolecall`
  build/               — clang output (generated by `make`); gitignored
  Makefile             — clang → build/<stem>.bpf.o, + rolecall target
  README.md            — build + run instructions
  .gitignore           — /build/
```

The generated `main.js` exercises the three most common surfaces:
`RingBuf` subscription, `DataSec` reads, and `attach`. Strip whatever
you don't need.

## Usage

```sh
example/bootstrap/bootstrap.sh <name> [--dest <dir>] [--force]
```

- `<name>` — project directory name. Normalized to a kebab-case slug
  for filenames and a C identifier for prog/struct symbols.
- `--dest <dir>` — parent directory (default: cwd). Pass `--dest example`
  to drop the new project next to the others.
- `--force` — overwrite existing files in the target directory.

### Examples

```sh
# Scaffold ./my-probe in the current directory.
example/bootstrap/bootstrap.sh my-probe

# Scaffold example/my-probe alongside the other built-in examples.
example/bootstrap/bootstrap.sh my-probe --dest example
```

After scaffolding, build the BPF object inside the Lima VM (macOS) or
directly (Linux):

```sh
cd example/my-probe
make                   # writes build/my_probe.bpf.o
./bin/my-probe         # or ./src/main.js, or yeet run ./src
```

## Notes

- The script is plain bash, no dependencies, no install step.
- Templates live in `template/` alongside the script with placeholders
  `__NAME__`, `__SLUG__`, `__STEM__`, `__OBJ_STEM__`. They get
  substituted in both file contents and path segments (e.g.
  `template/src/bpf/__STEM__.bpf.c` →
  `<name>/src/bpf/<stem>.bpf.c`). Edit the templates to change the
  default starter shape (e.g. a `HashMap` starter instead of a ringbuf
  starter).
- The C identifier is derived from the slug (`my-probe` → `my_probe`),
  so the generated prog is `my_probe_count` and the ringbuf event
  struct is `my_probe_event`. Rename freely once scaffolded.
